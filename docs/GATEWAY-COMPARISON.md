# APIM gateway accelerator and Claude apps gateway compared

- **Date:** 2026-09-27
- **Route A, APIM gateway accelerator:** [naveenneog/claude-code-foundry-gateway](https://github.com/naveenneog/claude-code-foundry-gateway)
  at commit `ea31a5f` (2026-09-27). Claude Code sends the developer's Entra token to Azure API
  Management, which calls Microsoft Foundry with its managed identity.
- **Route B, Claude apps gateway:** Anthropic's self-hosted gateway, `claude gateway --config gateway.yaml`,
  from the documentation retrieved 2026-09-27 (the newest version it names is Claude Code 2.1.283), and
  tested in this repository with 2.1.280 on Azure Container Apps ([ADR-0003](adr/0003-azure-test-deployment-with-restricted-ingress.md)).
- **Evidence:** links marked `apim:` are permalinks into the accelerator at `ea31a5f`. "Measured" marks a
  result recorded with a date in the cited file; "researched" marks a documented finding in this
  repository's unknowns register; "priced" marks a list-price calculation recorded with a date;
  everything else is documented behaviour.
- This document replaces the route A facts in the comparison in [ADR-0002](adr/0002-pilot-claude-apps-gateway-alongside-apim.md),
  which describe the accelerator as it was before 2026-09-23. ADR-0002's decision, a pilot of route B
  decided in P-16, is unchanged.

## Summary

- Both routes call Foundry with a managed identity, so Foundry attributes all usage to one gateway
  identity. Per-developer attribution lives in the gateway: route A keys it on the developer's own Entra
  token, validated by APIM on every request; route B keys it on a session token that the gateway signs
  after an Entra sign-in.
- Route A runs on a managed Azure service, serves CI identities and developers on the public internet,
  keeps the Claude Code feature set of a direct Foundry connection, and enforces per-developer token
  rates and shared quotas. Its USD budgets are reconciled every five minutes.
- Route B adds SSO sign-in with no Azure credential on developer machines, per-IdP-group model lists and
  settings delivered by the gateway once an administrator-controlled managed source on each machine
  names it, USD caps checked before each request with warnings in Claude Code, and per-request failover
  across upstreams. It is a self-hosted Linux service with PostgreSQL on a private network, has no
  unattended service-token flow and no inference rate limit, and turns off two features a direct
  Foundry connection has: the 1-hour cache TTL, and server-side web search on deployments hosted on
  Anthropic.
- Measured here from 2026-09-23 to 2026-09-26: route B boots on Azure, serves its sign-in endpoints,
  enforces its address allow list and costs 1.20 USD a day as a test deployment. Its inference path to
  Foundry is not measured yet: those checks need a person to complete a browser sign-in.

## How each route carries a request

- **Route A.** `az login`, then Claude Code sends an Entra access token for the Foundry audience. APIM
  validates it ([apim:infra/policy.xml:32-42](https://github.com/naveenneog/claude-code-foundry-gateway/blob/ea31a5fd242ee11fcb94c5ee2d2e6935d6ebcbdc/infra/policy.xml#L32-L42)),
  checks entitlement, the tier's model list, token limits and USD state for the token's `oid`, records the
  request, replaces the token with its managed-identity token and forwards to Foundry
  ([apim:infra/policy.xml:716-734](https://github.com/naveenneog/claude-code-foundry-gateway/blob/ea31a5fd242ee11fcb94c5ee2d2e6935d6ebcbdc/infra/policy.xml#L716-L734)).
- **Route B.** `/login` runs a browser sign-in against Entra; the gateway issues its own session token.
  Claude Code sends that token; the gateway checks it, the group's model list and spend caps, writes audit
  events and calls Foundry with its managed identity
  ([overview](https://code.claude.com/docs/en/claude-apps-gateway#why-claude-apps-gateway),
  [Foundry upstream](https://code.claude.com/docs/en/claude-apps-gateway-config#microsoft-foundry)).

## Advantages and disadvantages

### Route A: APIM gateway accelerator

Advantages:

- A Microsoft-managed gateway. The default named-value profile adds no container, database or TLS certificate to operate; the optional projection adds Cosmos DB and a Function (rows "What you operate", "Platform cost").
- Every request carries the developer's own Entra token, validated by APIM; attribution keys on its `oid` (rows "Developer sign-in", "Telemetry and audit").
- CI and unattended identities use the same gateway, measured with a managed identity and a service principal (row "CI and unattended callers").
- Per-developer token and call rate limits, plus organisation and business-unit quotas shared by their members (rows "Inference rate limits", "Shared quotas").
- A public endpoint by default, with private and WAF options; developers off the corporate network need no VPN (row "Network exposure").
- The Claude Code feature set of a direct Foundry connection, including the 1-hour cache TTL and web search on deployments hosted on Anthropic (row "Claude Code features").
- Business-unit chargeback ledger, workbooks and e-mailed monthly reports (row "Cost attribution and chargeback").

Disadvantages:

- Developer machines need the Azure CLI and an Entra sign-in for the Foundry audience (rows "Developer sign-in", "Credential on the developer machine").
- Access changes wait for a sync run. The default store holds about 93 developers in business-unit lists and 110 per tier list; beyond that the Cosmos DB projection is needed (rows "Who may call", "Removing access").
- Client settings depend on MDM or an administrator-installed managed-settings file; a device without either gets none (row "Client settings").
- USD budgets stop spending after a delay made of log ingestion, a five-minute reconcile schedule and APIM propagation; token caps are soft (rows "USD budgets", "Inference rate limits").
- Streaming bodies are not metered in policy; cache writes on streams are unknown (row "Streamed responses").
- One Foundry backend without failover (row "Upstream failover").
- An empty model list allows every deployed model (row "Model access").
- Entra ID only (row "Identity providers").
- An APIM tier with a private endpoint starts at about $700 a month (rows "Network exposure", "Platform cost").
- The accelerator maintains its own API surface: two operations, no `/v1/models` (row "Protocol surface").

### Route B: Claude apps gateway

Advantages:

- SSO sign-in; developer machines hold no Azure CLI or cloud credential (rows "Developer sign-in", "Credential on the developer machine").
- Membership read from the token at each sign-in and refresh; no sync job and no member list held by the gateway. Entra's 200-group limit on the groups claim still applies (row "Who may call").
- Model lists and managed settings per IdP group, delivered by the gateway; MDM or an administrator sets only the gateway URL on each machine (rows "Model access", "Client settings").
- Claude Desktop through the same sign-in and group policy (row "Claude Desktop").
- USD caps checked before each request against recorded spend, with warnings in Claude Code; the request that crosses a cap completes (row "USD budgets").
- Per-request failover across upstreams (row "Upstream failover").
- The protocol is maintained by Anthropic with each Claude Code release (row "Protocol surface").
- Any OIDC identity provider (row "Identity providers").
- No licence fee. The measured test deployment, one replica with a PostgreSQL sidecar, cost 1.20 USD a day; production cost is not measured (row "Platform cost").

Disadvantages:

- A self-hosted Linux service with PostgreSQL, TLS and private DNS. Fixes, security fixes included, arrive only when the operator updates the pinned version and redeploys; Anthropic publishes no Azure deployment guide (rows "What you operate", "Azure deployment guidance", "Versions and upgrades").
- `/login` needs a private address; developers off the network need VPN (row "Network exposure").
- No unattended service-token flow; CI calls Foundry directly (row "CI and unattended callers").
- No inference rate limit and no shared quota pool (rows "Inference rate limits", "Shared quotas").
- The 1-hour cache TTL, and server-side web search on Foundry deployments hosted on Anthropic, both available on a direct Foundry connection, are off on gateway sessions (row "Claude Code features").
- Failover retries a down upstream on every request, with no record of failures; for Foundry a request can wait up to one hour (row "Upstream failover").
- An admitted user who matches no group policy gets every model and no managed settings unless a catch-all policy comes last (row "Model access").
- The IdP app needs a client secret; in the test tenant it lasts at most 30 days (row "Identity providers").
- With spend limits, PostgreSQL holds identities and spend; when it is unreachable, spend checks fail open by default, and an orchestrator that routes on `/readyz` stops all traffic (rows "Personal data held", "When a dependency fails").
- Its inference path to Foundry is not measured yet in this repository (row "Maturity and evidence").
